## 共享任务入口

POST /v1/jobs 接收 idempotency_key 和 input，input.mode 支持 e11-a、e11-b、e12。repo/base/target 为必填，输入路径指向 API 宿主的 /course/data。E12 请求包含 candidate。项目配置使用已有 profile=true 与 project_path。成功返回202和任务状态，同键同输入返回同一 job_id，同键改 target 返回409 IDEMPOTENCY_CONFLICT，原任务内容与队列保持一致。

GET /v1/jobs/{job_id} 返回任务状态。GET /v1/jobs/{job_id}/artifacts 返回本任务实际 result.json。GET /v1/jobs/{job_id}/files/{path} 下载原始字节，响应头 X-Content-SHA256 与 result.artifacts 中对应 uri 的 sha256 及实际下载内容三处一致。

mode=e12 的成功任务阶段顺序为 draft、full-check、incremental-check、repair、recheck。同一任务 job_id/trace_id 一致，full-check.commit 对应 base，其他阶段对应 target。repair.data.input_report 指向本轮 incremental-check 的原始字节摘要。

## A 侧报告交接出口

GET /v1/jobs/{job_id}/reports/incremental-check?target={40位完整SHA} 返回交接清单。

```json
{
  "schema_version": "e11e12-transfer-1",
  "kind": "incremental-check",
  "job_id": "job-实际任务",
  "trace_id": "trace-实际跟踪",
  "commit": "目标完整SHA",
  "report": {
    "uri": "artifact://job-实际任务/incremental-check.json",
    "sha256": "原始封装文件的SHA256",
    "bytes": 0
  },
  "download_path": "/v1/jobs/job-实际任务/files/incremental-check.json"
}
```

示例中的标识、哈希和字节数须取实际响应。出口只接受成功任务，校验阶段清单中的URI、原始文件哈希/大小、封装schema/kind/status/commit、job/trace以及data.commit。请求旧target返回409 STALE_REPORT，目标格式错误返回400 INVALID_TARGET，内容篡改返回409 ARTIFACT_HASH_MISMATCH，身份不匹配返回409 REPORT_IDENTITY_MISMATCH。

B3 从另一端取得清单，再通过 download_path 下载原始增量封装。核对三处哈希、外层commit与data.commit，交给B2的修复入口时使用封装内data，保留原始封装、清单、下载响应头、独立消费输出与原任务来源。传递已下载的报告应保存原字节，重写JSON会改变其摘要。
