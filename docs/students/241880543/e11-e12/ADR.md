# ADR · 将 MDFixer 的修复约束在报告目标上

- 角色与学号为 B2 / `241880543`。
- 决策日期为 2026-11-16。
- 范围为 E11-B 与 E12 的 MDFixer 输入及 Make 前置依赖编辑。

## 背景

一个看似属于 `main.o` 的纯宏规则 `main.o: $(DEPS)` 可能与 `helper.o` 共用 `DEPS`。把 `config.h` 和 `extra.h` 加入变量定义会改变其他使用该变量的规则。与此同时，MD 报告可能在外层标注当前 target，却携带另一提交的 `data.commit`。摘要只能确认报告字节的完整性，提交身份由报告内容和实际目标的比对确定。

## 决策

E11/E12 调用既有 `patch()` 时启用 `isolate_shared_macros`。对于纯宏规则，若宏在 Makefile 中只有该处引用，沿用编辑变量赋值的定位。若宏有其他引用，在报告目标的规则行追加具体头文件，保留该行的宏引用，并把计划中的风格记录为 `mixed`。直接声明和已有混合声明均在目标行处理。E8–E10 的调用沿用 `patch()` 默认行为。[补丁实现](../../../../labs/e8e10/lab.py)

E11-B 的固定报告在发布 `fixed-md` 阶段前校验 `schema_version`、报告类型、状态及两层提交。流水线准备生成补丁时，使用阶段工件引用校验磁盘字节，再调用公共 `repair_input()` 检查预期类型与目标提交。外层或 `data.commit` 指向旧提交时，返回 `STALE_REPORT`，补丁阶段由此终止。[编排实现](../../../../labs/e11e12/pipeline.py)

构建、运行和头文件变化测试沿用公共项目配置；E12 将 DRAFT 返回的不可变镜像 ID 传入执行器。每次执行的实际容器镜像和退出码随验证、重检记录留证。[项目配置](../../../../projects/transfer-eta/e12-profile.json) · [DRAFT 执行器](../../../../labs/e11e12/draft_fullcheck.py)

## 验证与适用范围

| 试例 | 独立判据 |
| --- | --- |
| 两个对象目标共用 `DEPS` | 应用补丁后恰好替换 `main.o` 一行，新增 `config.h` 和 `extra.h`，`helper.o` 的展开依赖集合前后相等。 |
| 固定报告外层为当前目标，`data.commit` 为基线 | `STALE_REPORT`，阶段停在 DRAFT，生成补丁和复验函数零调用，修复产物缺席。 |
| 增量报告摘要正确，`data.commit` 为旧值 | 摘要检查通过后仍返回 `STALE_REPORT`。 |
