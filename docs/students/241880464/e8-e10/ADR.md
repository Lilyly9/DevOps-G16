# ADR：配置身份变化必须使历史依赖图失效

2026-11-03，A3 林涵 / 241880464。状态：本轮采用并验证。

## 背景与约束

本人按助教要求独立完成A轨E8/E9/E10。保留原分工的核心函数维护边界，本轮增加三个独立输入/断言，不改共享检测逻辑。仅修改函数体可以复用实际图，但CFLAGS中的宏会改变条件include是否生效。只比较源码文本或发现数量，可能漏掉新增边。

## 选择与替代方案

采用课程现有key：本地.c/.h预处理行集合、配方、CFLAGS、编译器版本共同绑定历史图身份。只要该key变化，保守刷新两个对象；每次重新解析声明并重新计算findings。新增-DMODE=1场景显式证明配置变化能够使原来不读取的mode.h成为真实依赖。

替代一是始终全量扫描，简单但不能展示历史复用。替代二是只比较include行，成本低但无法识别宏改变。替代三是逐目标精确失效，可能减少helper.o冗余刷新，但需要更完整的配置传播与依赖证明，本轮未实现。

## 代价与覆盖范围

保守刷新使helper.o也重新扫描，小样例扩展full/inc=0.9860，实际略慢；接受此代价以保证受限范围内完整集合一致。仍只支持两对象、简单显式Make、允许的三种CFLAGS；不声称处理外部工具链动态变化、复杂隐式规则或完整论文规模。

## 验证

正式标准OUT work/e10-A-manual.dAyEb0 六类各5次；自主OUT work/e10-A-manual.1v1wdC宏场景5次；8项统一发现测试。check手写actual/declared/findings、added/resolved及复用/刷新预期；最终标准另有真实BuildChecker对象图重检。详见本人报告和e10/evidence/A3-241880464/原件。

## E8/E9补充决策

E8采用按目标区分共享头边，拒绝把同名shared.h读取仅合并成单条发现；用main.o间接读取与helper.o直接读取的真实trace分别核对。E9除新增include外再验证移除include：保留leaf.h文件，只改变预处理结构，使旧边必须从图中移除；不能仅根据文件仍存在而复用旧图。只补声明时继续复用actual，但重新计算findings。两项测试有手写完整图/发现、added/resolved预期。
