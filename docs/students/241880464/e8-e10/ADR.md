# ADR：配置身份变化必须使历史依赖图失效

2026-11-03，A3 林涵 / 241880464。状态：本轮采用并验证。

## 背景与约束

A3负责E10验证，A2维护scan核心；本轮选择增加独立输入和断言，不改共享检测逻辑。仅修改函数体可以复用实际图，但CFLAGS中的宏会改变条件include是否生效。只比较源码文本或发现数量，可能漏掉新增边。

## 选择与替代方案

采用课程现有key：本地.c/.h预处理行集合、配方、CFLAGS、编译器版本共同绑定历史图身份。只要该key变化，保守刷新两个对象；每次重新解析声明并重新计算findings。新增-DMODE=1场景显式证明配置变化能够使原来不读取的mode.h成为真实依赖。

替代一是始终全量扫描，简单但不能展示历史复用。替代二是只比较include行，成本低但无法识别宏改变。替代三是逐目标精确失效，可能减少helper.o冗余刷新，但需要更完整的配置传播与依赖证明，本轮未实现。

## 代价与覆盖范围

保守刷新使helper.o也重新扫描，小样例扩展full/inc=0.9860，实际略慢；接受此代价以保证受限范围内完整集合一致。仍只支持两对象、简单显式Make、允许的三种CFLAGS；不声称处理外部工具链动态变化、复杂隐式规则或完整论文规模。
