# ADR A3-01 增量报告出口与执行身份

2026-11-15，林涵 / 241880464，状态为本轮已实现并验证。

问题是下游需要确认收到的报告来自哪次成功检测、属于哪个目标提交，以及字节是否仍匹配生产方清单。只给文件路径或在JSON中传image_id不能完成这些核对。

采用原e11e12-1封装和新e11e12-transfer-1交接清单。生产方从成功任务的阶段清单取得incremental-check.json的URI、大小和摘要，验证原始文件、外层/内部commit及job/trace后导出下载路径。客户端保持原始字节，分别核对清单、HTTP响应头、实际文件。B侧消费可在独立模块接入，保留自己的输入和复验，不要求共享生产方目录。

复用已有HTTP文件接口可减少新协议。直接将JSON重新序列化再交接会改变原始哈希；本轮选择原字节下载。目标SHA为显式必填，便于在触发修复前拒绝旧报告。相同幂等键冲突保持原任务和队列，故障重试另取新键。

执行身份沿用A1的DraftExecutor，A3仅取消固定样例上两处profile条件，使所有E12的扫描与构建/程序/头变化复验都调用该执行器。以容器inspect记录比对不可变DRAFT image_id，保存每条命令及真实退出码。将执行器TimeoutError统一归因为TIMED_OUT/TIMEOUT并落盘。

代价包括额外容器启动开销与分次下载日志。当前接口面向固定C/Make及A1已有profile范围，B3本人独立消费与课程项目认可仍需对应验收。十三项A3独立测试与原测试共37项通过，云端CLI/API、SSH下载、旧提交拒绝、服务重启与完整字节审查均已留证。
