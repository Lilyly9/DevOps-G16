## 5. `prepare_candidate()` 的真实行为

源码：[autobuild.py](../../e5/B-draft/services/draft/draft/autobuild.py)，函数位于第 28–49 行，调用位于第 82–83 行。

它接收两个 **Dockerfile 文本字符串**：`broken` 是原始失败 Dockerfile，`candidate` 是外部保存的候选 Dockerfile。路径读取由 `auto_build()` 负责；该函数自身不读文件、不调用模型，也不识别候选提供商或验证来源真实性。

1. 调用 `instructions()`：忽略空行和整行注释，合并反斜杠续行并规范化空白；未结束的续行会报错。
2. 要求两个指令列表均非空。候选首行必须精确匹配 `FROM <非空白镜像>@sha256:<64位小写十六进制>`，并且只能有一个 `FROM`。
3. 去掉候选首行的 digest 后，要求基础镜像标签与原始首行完全相同。
4. 用候选的固定 digest 首行替换原始 `FROM`，其余原始指令保持顺序，得到 `baseline`。
5. 顺序扫描候选：保留的基线指令必须全部出现且顺序一致；其余指令只允许以大写 `RUN ` 开头，并且至少新增一条。修改 COPY、构建指令或 CMD 等必需指令、遗漏原始指令都会拒绝。函数没有进一步分析新增 RUN 是否安装了 make、是否安全或是否有效，实际效果依赖后续构建与运行。
6. **返回的是规范化的失败基线 Dockerfile 文本**，不是最终修复候选。第一轮使用返回值，第二轮使用读取到的完整候选文本（第 96 行）。这样两轮使用同一个基础镜像 digest，第一轮仍保留原来的 `RUN make`，新增安装步骤只在第二轮执行。

候选来源由入口处理：`lab_cloud.py` 第 121–126 行选择显式 `--candidate` 文件或 `--replay` 对应的 `fixtures/ci-candidates/DeepSeek-E5.Dockerfile`，记录候选原始字节哈希和来源标签；文件通过只读挂载传入服务容器。`auto_build()` 第 86–88 行将流程标为 `DRAFT_TEACHING_REPLAY`，保存候选文本的 UTF-8 哈希，声明没有模型/API 调用。包内 `provenance.json` 是已有 DeepSeek 教学候选的记录，不代表本次重新生成候选。

本次静态调用返回的基线见 `preflight-01/prepared-baseline.txt`；其内容仍有 `RUN make`，没有安装 build-essential 的新增 RUN。接受候选并不表示构建通过。

## 7. 输入哈希方法与 Windows 行尾差异

`auto_build()` 第 92–95 行先复制 fixture 为 `project/`，忽略 `.git`、`.env`、`.env.*`、`work`、`__pycache__` 和 `Dockerfile.reference`；之后遍历 `sorted(project.rglob("*"))` 中每一个 `is_file()` 的路径，用相对 POSIX 路径作为键，值为 `hashlib.sha256(p.read_bytes()).hexdigest()`。

这是一张逐文件原始字节哈希表，没有拼接成“目录总哈希”，也没有先读取文本、转换换行或只挑选 main.c/Makefile。独立复核应对**实验保存的 `project/` 副本**使用相同算法，检查键集合与值；课程验证脚本第 40–45 行还会拒绝逃逸到 project 外的路径，并按记录逐项核对。

本机 `git config --show-origin --get core.autocrlf` 为系统配置 `true`，`git ls-files --eol` 确认候选索引为 LF、工作区为 CRLF，因此本机候选原始字节 SHA-256 为：

```text
3473d3d2d26c3c20b3a899c7c061992fabe96bb7227e6666ad67390a77dd8f98
```

`read_text(encoding='utf-8')` 的通用换行处理后，再 UTF-8 编码计算得到：

```text
ede21b0fab394071641526e2fccefc41565efb00de6fb54d9d5b906aebeb535d
```

后者与包内 provenance 相同。这解释了静态阶段观察到的差异；**不构成本次 E6 输入哈希验证通过**。没有修改候选、全局行尾配置、哈希算法或 JSON 报告。应在 Linux 的正常 Git 检出中运行，并对已保存的证据按原始字节验证；不要为迁移证据转换行尾。归档使用局部 `.gitattributes` 保留日志与 JSON 字节。
