## 1. 复现说明

### 1.1 真实失败(E5 核心)

`lab_cloud.py e5` 把 fixture 复制为 `work/e5-B1-01/project/`,用它自带的故障 Dockerfile(`iter-01/Dockerfile`,FROM `python:3.13-slim@sha256:70729b46…`,无 make/gcc)执行真实 `docker build --progress=plain`:

- 构建到达 `RUN make` 后失败:`/bin/sh: 1: make: not found`(exit 127),外层 docker build 退出码 **1**;
- `iter-01/result-retry.json`:`{"build_exit_code": 1}`;
- `iter-01/build-retry.log` 第 30/34 行两处 `make: not found`;
- `iter-01/error-localization.json`:`provenance=SCRIPT_FROM_ACTUAL_BUILD_LOG`,根因行即上述两行,无人工修饰;
- 采集脚本自身退出码 **0**。

**两层退出码的含义**:构建退出码 1 是"目标故障"——基础镜像缺 make,构建应当失败,DRAFT 流水线的职责是把这次失败原样记录为证据;脚本退出码 0 是"采集任务成功"——复现失败、保存日志、生成提示的流程全部完成。把这两个数混为一谈(比如"脚本没报错所以构建成功")是错误的。

脚本从失败构建生成两类提示(`iter-01/prompt-error-driven.txt` 62 行;`iter-01/prompt-context-driven.txt` 73 行,额外含 README 上下文)。两类提示的**全文**分别提交给对话模型(Claude Sonnet 4.6,Claude Code CLI 会话),得到两个候选:

| candidate-02 | context-driven | `apt-get install build-essential`(对应 README 声明的 "A C compiler and GNU Make") |

两个候选都保留 pinned FROM digest(`70729b46…`)、WORKDIR、COPY、`RUN make`、`CMD ["./hello"]`,未绕过构建。最终选择 candidate-02(与 README 依赖描述 1:1 对应)。原始回复 verbatim 存于 `candidate/model-response.txt`;候选文件已去围栏;来源记录见 `candidate/候选来源记录.json`(`is_recorded_replay: false`)。

## 3. 环境故障记录(非功能失败)

以下问题全部是环境/网络层故障,处理过程如实记录,均不构成对 DRAFT 功能的判断:

1. **docker.io 直连被 DNS 污染**(解析到 Dropbox/Facebook 段 IP):三个基础镜像直连拉取全部超时。处理:`/etc/docker/daemon.json` 配 `registry-mirrors`(docker.m.daocloud.io)。
2. **buildkit 对 digest 引用必联网 resolve**:本地已有镜像不能跳过 registry 查询;配 mirror 后 `# syntax=docker/dockerfile:1` 前端与基础镜像元数据解析恢复。
3. **容器内 DNS 回退 8.8.8.8 丢包**(宿主机 systemd-resolved 127.0.0.53):apt 前 700 秒近乎停滞。处理:daemon.json 加 `"dns": ["223.5.5.5", "119.29.29.29"]`。
4. **ECS 公网带宽小**(实测 ~100 KB/s 量级;内网镜像 36.7 MB/s):服务镜像构建在 1200s 超时内无法完成 apt+pip 下载。处理:`--build-timeout` 提到 3600s(build-B1-05 成功,24 passed)。
5. **apt 解包 gcc 工具链时 OOM**(anon-rss 3.3 GiB > 3.5 GiB 物理内存,内核 oom-killer 杀掉 apt-get,build 退出 137):第 1 次候选复建失败。处理:临时创建 4G swap(`/swapfile`,未写 fstab)后重跑。记录更正:第 1 次失败日志(`build-e5.log`)在第 3 次运行时因脚本命名失误被覆盖,失败证据以内核 dmesg(`docker-buildx invoked oom-killer … Killed process … (apt-get) total-vm:3322200kB, anon-rss:3303900kB`)与错误文本 `ERROR: … exit code: 137` 为准。
6. **公网链路晚高峰退化至 ~10 KB/s**(第 2 次复建 apt 下载 90+ 分钟未完成,人工终止):改用宿主机 squid 正向代理(originserver + forceddomain)把 `*.debian.org` 请求转发至阿里云内网镜像 `mirrors.cloud.aliyuncs.com`,并经 `~/.docker/config.json` 的 `proxies.default` 注入容器与构建(`daemon.json` 的 `proxies` 段只作用于 dockerd 自身拉取,不注入容器)。apt 元数据下载由 20+ 分钟降到 1.2 秒,第 3 次复建数分钟内完成。第 2 次的中断日志保留于 `candidate/build-e5-02.log`。
7. doctor 报告内存 3.5 GiB 低于最低要求 4(必需项)、CPU/磁盘低于建议值:按 §11 记录实际值,本次未影响功能结论。
